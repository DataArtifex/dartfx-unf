# UNF v6 JSON Report Format

This document describes the structure of the JSON reports generated by `dartfx-unf`. The format is designed to be fully compliant with the UNF v6 specification across all three levels of granularity.

## Levels of Hierarchy

The JSON structure reflects the recursive nature of the UNF algorithm:

1.  **Column Level (Vector)**: The leaf nodes. Each column in a file is normalized and hashed individually.
2.  **File Level (Data Frame)**: An aggregate of column UNFs. Following the spec, columns are sorted by their printable UNF strings (POSIX locale) before being combined.
3.  **Dataset Level (Study)**: An aggregate of multiple File UNFs. Useful for verifying entire multi-file research collections.

## Schema Fields

### `metadata`
- **`parameters`**: Captures the exact settings used for the calculation. This is critical because UNF headers (`UNF:6:N9:...`) change based on these values.
  - `N`: Significant digits (Default: 7).
  - `X`: String truncation length (Default: 128).
  - `H`: Hash bits for truncation (Default: 128).
- **`rounding_mode`**: Distinguishes between standard IEEE 754 rounding and the optional `R1` truncation mode mentioned in the spec.

### `result`
- **`type`**: Indicates if the root result is a `file` or a `dataset`.
- **`unf`**: The calculated fingerprint for that level.
- **`entries / columns`**: The constituent parts used to derive the parent UNF.

## Sorting and Reproducibility
The UNF specification requires that when combining column UNFs into a File UNF (or File UNFs into a Dataset UNF), the signatures must be **sorted in POSIX locale order**.

The JSON report preserves the order of columns as they appear in the file for human readability, but the `unf` value at the file/dataset level is calculated using the sorted signatures as per the spec.

## Validation
A formal JSON Schema is available at `unf.schema.json`.
